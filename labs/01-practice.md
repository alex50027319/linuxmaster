# 자체 실습과 확인 기준

아래는 원문 문제의 복제가 아닌 자체 과제입니다. 명령을 실행하기 전 관련 주제를 읽고, 변경을 할 때마다 결과를 확인합니다. 기대 결과가 맞아야 완료로 기록합니다. `[ ]`를 모두 채웠다는 이유로 모든 기출의 정답이 검증되었다고 표시하지 않습니다.

## 1. 계정·그룹·권한

- [ ] `labuser`를 홈과 함께 만들고 `labteam`을 보조 그룹으로 추가합니다. `id`에서 기존 보조 그룹이 유지되는지 확인합니다.
- [ ] 셸을 nologin으로 바꾸고 `getent passwd`로 확인한 뒤 복원합니다.
- [ ] 암호 최대 60일, 경고 10일, 만료 뒤 7일 유예를 설정하고 `chage -l`의 각 항목을 설명합니다.
- [ ] 그룹 공유 디렉터리에 SGID·Sticky를 주고 두 사용자로 파일 생성·삭제를 시험합니다. 권한 숫자만 맞히는 것과 실제 동작 확인을 구분합니다.

정리: 연습 계정·그룹·디렉터리만 제거하거나 스냅샷 복원. [주제](../topics/users-permissions.md)

## 2. 프로세스·예약 실행

- [ ] sleep을 nice 값 7로 실행하고 renice로 12로 바꿉니다. `ps`에서 같은 PID의 NI가 바뀌는지 확인합니다.
- [ ] 자신의 crontab에 1분마다 시각을 파일에 기록하는 작업을 넣습니다. 연속 2회 기록을 확인하고 그 줄만 제거합니다.
- [ ] 개인 crontab 줄을 `/etc/cron.d/` 형식으로 바꿀 때 추가할 칸을 설명합니다.

정리: 연습 PID 종료, 추가한 cron 줄 제거. [주제](../topics/processes-cron.md)

## 3. 파일 백업·복원

- [ ] 하위 디렉터리와 공백 있는 파일명을 포함한 연습 트리를 만듭니다.
- [ ] tar.gz와 newc 형식 cpio로 각각 백업하고 내용을 조회합니다.
- [ ] 두 개의 새 폴더에 복원하여 `diff -r`로 비교합니다.
- [ ] rsync의 source 끝 슬래시 유무로 목적지 구조가 어떻게 달라지는지 확인합니다.

정리: 홈의 해당 연습 폴더만 제거. [주제](../topics/backup-restore.md)

## 4. DNS 파일 연습

- [ ] `named-checkzone example.test examples/dns/example.test.zone`과 역방향 파일 검사를 통과합니다.
- [ ] 새 호스트 `api`의 A와 대응 PTR을 추가하고 serial을 올립니다.
- [ ] 끝 점을 누락했을 때 FQDN이 어떻게 해석되는지 설명합니다.
- [ ] 별도 VM 서비스에 적용할 경우 dig로 A·MX·PTR을 질의해 기대한 이름/주소가 나오는지 확인합니다.

파일 문법 검사와 실제 질의 성공은 별도로 기록합니다. 정리: 복사본 삭제 또는 VM 설정 복원. [주제](../topics/dns.md)

## 5. 로그·설정 검사

- [ ] local0.notice 전용 rsyslog 파일을 만들고 `logger`의 고유 marker가 기록되는지 확인합니다.
- [ ] logrotate를 `-d`로 검사하고 실제 회전 시 보관 개수·소유자·모드를 확인합니다.
- [ ] sysctl 키와 `/proc/sys` 경로가 같은 값을 보여주는지 비교합니다. 변경했다면 원래 값으로 복원합니다.

정리: 추가한 rsyslog·logrotate·sysctl 설정만 복원. [주제](../topics/logs-sysctl-ipc.md)

## 6. 빈 디스크 전용 실습

이 과제 전용 스냅샷을 저장합니다. 디스크마다 용도 표를 작성하고 시스템 디스크는 제외합니다.

- [ ] fdisk로 전체 크기의 GPT 파티션 하나를 만들고 ext4 → mount → 파일 작성 → unmount/remount 후 파일 유지까지 확인합니다.
- [ ] 초기 상태로 복원한 뒤 parted로 같은 목표를 달성합니다. mkpart 직후와 mkfs 직후의 `lsblk -f`를 비교합니다.
- [ ] 별도 빈 디스크들로 RAID1을 만들고 `/proc/mdstat`와 `mdadm -D`로 상태를 확인합니다.
- [ ] 다시 초기 상태에서 PV → VG → LV → XFS → mount를 만들고 LV와 파일시스템을 각각 확장해 용량을 확인합니다.
- [ ] 전용 파일시스템에서 사용자 쿼터를 활성화하고 일반 사용자로 실제 제한을 시험합니다.
- [ ] 파일시스템 종류에 맞는 백업을 만든 뒤 새 경로로 복원해 비교합니다. dd는 마운트 해제된 별도 장치만 사용합니다.

정리: 파일시스템·RAID·LVM 순서를 이해하고 스냅샷 복원. [스토리지](../topics/storage-raid-lvm-quota.md), [백업](../topics/backup-restore.md)

## 7. 서비스별 확인 목표

| 주제 | 최종 확인 기준 |
|---|---|
| Apache | configtest 통과, 가상 호스트 Host 헤더에 맞는 응답, 인증 전401/인증 후 정상 응답 |
| Samba | testparm 통과, 허용 사용자 접속·읽기·쓰기, 미허용 사용자 거부 |
| NFS | exportfs 확인, 클라이언트 mount, root_squash 조건에 맞는 파일 소유자 |
| vsftpd | user_list/PAM 정책에 따른 허용·거부, 업로드 디렉터리 권한 확인 |
| Sendmail | 텍스트 맵과 DB 갱신, 로컬 계정에만 시험, 로그·수신 결과 확인 |
| Squid | parse 통과 후 실제 허용·차단 요청과 access.log 비교 |
| DHCP | 격리 NIC의 클라이언트가 원하는 풀·DNS·게이트웨이를 임대받음 |
| 방화벽/NAT | 다른 VM에서 허용·차단을 각각 검사, 규칙 카운터와 반환 경로 확인 |
| SSH | 기존 접속을 유지하고 새 공개키 세션 성공, root 정책도 별도 확인 |

서비스마다 별도 스냅샷과 연습 네트워크를 사용합니다. 어느 하나의 문법 검사 성공을 이 표 전체 성공으로 기록하지 않습니다.

## 오답 복습

원문 한 회차를 자료 없이 풀기 → ID로 색인 검색 → 조건과 예제의 차이를 적기 → VM에서 확인 → 자료를 닫고 다시 풀기 순서를 반복합니다. 시험지에 명령·옵션·절대경로·설정값 중 무엇을 요구하는지도 별도로 표시하세요. 여러 동등한 명령이 가능해 보여도 문항의 지정 도구·앞뒤 문법·배포판 조건을 우선합니다.
