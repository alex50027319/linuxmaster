# linuxmaster

리눅스마스터 1급 실기를 **Rocky Linux 8 계열 VM에서 연습**하기 위한 한국어 참고 자료입니다.

연결한 기출 모음의 11개 회차·176문항을 주제별로 연결한 색인, 직접 작성한 개념·명령어·설정 예제, 실습 과제를 제공합니다. 원문 문제와 정답 전체를 복제한 자료나 공식 정답집이 아닙니다. 색인 등록과 실제 명령 실행 검증은 구분하며, 검증 범위는 [검증 기록](VERIFICATION.md)에 적습니다.

## 다른 컴퓨터에서 받기

다음은 Rocky Linux VM 터미널에서 실행합니다. 처음 다운로드할 때만 인터넷이 필요합니다. `wget`이 없다면 먼저 `sudo dnf install wget`을 실행합니다.

```bash
wget -O linuxmaster.tar.gz https://github.com/alex50027319/linuxmaster/archive/refs/heads/main.tar.gz
mkdir -p linuxmaster
tar -xzf linuxmaster.tar.gz --strip-components=1 -C linuxmaster
cd linuxmaster
less REFERENCE.txt
```

이미 파일이 있는 폴더에 덮어쓰기보다 새 폴더에 풀어 연습 기록을 보존하세요. 고정 버전이 필요하면 `main` 대신 GitHub의 특정 커밋에 대한 archive URL을 사용합니다. 저장소 다운로드에는 Git 설치가 필요하지 않습니다. 패키지와 `man` 문서는 별도로 준비해야 합니다.

## 사용 순서

1. VM 스냅샷을 저장하고 `bash scripts/doctor.sh`로 명령·문서 설치 여부를 확인합니다. 이 스크립트는 설치·서비스 변경·디스크 수정을 하지 않습니다.
2. 원문에서 한 문항을 풀고 `coverage.md`에서 해당 ID를 찾습니다. 예: `2601-14`.
3. 연결된 주제에서 조건 → 문법 → 옵션 의미 → 검증 순서로 복습합니다.
4. 자체 실습은 [labs](labs/01-practice.md)의 기대 결과까지 확인합니다. 문법 검사 통과와 서비스 동작 성공을 구분합니다.
5. 정리본을 닫고 다시 풀고, `templates/review.csv`에 실패 원인과 재검증 결과를 적습니다.

예제 주소 `192.0.2.0/24`, `198.51.100.0/24`는 설명용입니다. 실제 VM 네트워크와 인터페이스 이름으로 바꿔야 합니다. 디스크 예제는 데이터를 지우므로 **추가한 빈 연습 디스크**를 `lsblk`로 식별한 뒤 필요한 명령만 직접 실행합니다. 이 저장소에는 자동 포맷 스크립트가 없습니다.

# VM 준비와 오프라인 문서 확보

## VM 구성

Rocky Linux 8.9 x86_64를 연습 기준으로 사용합니다. 다른 버전에서도 대부분의 개념은 같지만 지시어·기본값·패키지 가용성은 다를 수 있습니다. 설치 매체·저장소는 공식 경로를 사용하세요. 8.9처럼 과거 minor 버전을 고정하려면 일반 mirror 대신 해당 vault 구성을 검토해야 하며, `dnf update`로 버전이 바뀔 수 있습니다.

권장 연습 구성은 RAM 4GiB 이상, 시스템 디스크 30GiB 이상, 스토리지 실습용 빈 디스크 2–4개입니다. RAID6까지 직접 만들려면 최소 4개 구성원 디스크가 필요합니다. 스토리지 연습을 위해 시스템 디스크를 재분할하지 않습니다.

VirtualBox는 호스트 CPU와 가상화 지원에 맞는 게스트를 사용해야 합니다. Apple Silicon에서 x86_64 Rocky를 연습하려면 UTM/QEMU의 에뮬레이션 같은 별도 경로가 필요할 수 있습니다. 현재 VM의 실제 버전·장치는 다음으로 기록합니다.

```bash
cat /etc/rocky-release
uname -m
uname -r
lsblk -f
ip -br address
ip route
```

패키지 설치와 자료 다운로드에는 NAT NIC를 쓰고, DHCP·라우터 실습에는 별도의 내부 네트워크 NIC를 사용합니다. VM 여러 대가 필요한 과제는 서버·클라이언트를 같은 내부 네트워크에 두고 IP 충돌을 피합니다. 각 실습 전 전원을 안전하게 종료하고 스냅샷을 저장합니다. 스냅샷 자체도 호스트 고장에 대비한 백업을 완전히 대신하지는 않습니다.

## 기본 명령과 문서

아래 명령은 필요에 따라 **직접 선택해 설치**합니다. 저장소 가용성을 먼저 `dnf repolist`, `dnf info 패키지명`으로 확인합니다. 모든 패키지가 기본 설치되어 있다고 가정하지 않습니다.

```bash
sudo dnf install man-db man-pages less vim-enhanced wget bash-completion
sudo dnf install parted e2fsprogs xfsprogs mdadm lvm2 quota dump xfsdump
sudo dnf install tar cpio rsync cronie gcc make
sudo dnf install bind bind-utils httpd httpd-tools
sudo dnf install samba samba-client cifs-utils nfs-utils vsftpd
sudo dnf install squid dhcp-server sendmail sendmail-cf
sudo dnf install policycoreutils-python-utils nmap
```

별도 실습에 따라 firewalld·iptables 관련 패키지가 필요할 수 있습니다. 서로 다른 방화벽 관리 서비스를 무작정 동시에 켜지 않습니다. 패키지를 설치하는 것과 서비스를 시작·활성화하는 것은 다른 작업입니다. 시험용 명령 연습을 위해 오래된 서비스 전부를 인터넷에 공개할 필요도 없습니다.

```bash
man 8 useradd
man 5 crontab
man -k samba
apropos quota
rpm -qd squid
rpm -qc httpd
rpm -ql bind | less
```

`man`이 실패하는 이유는 프로그램 미설치, 해당 페이지 미포함, MANPATH·locale 문제 등입니다. `command -v 명령`, `man -w 페이지`, `rpm -q 패키지`로 나누어 확인합니다. `help`는 Bash 내장 명령용이고 `명령 --help`는 프로그램별 기능입니다. `sudo mandb`는 검색 DB 갱신이며 없는 문서 패키지를 설치하는 명령은 아닙니다.

## 커널 소스가 없는 경우

`/usr/src`가 비어 있어도 일반 Linux 명령 연습에는 문제가 없습니다. 커널 make 목표를 연습할 때는 공식 소스 tarball이나 배포판 소스를 별도 디렉터리에 풀고 `make help`를 읽습니다. [kernel.org](https://www.kernel.org/)에서 원하는 버전과 검증 자료를 확인합니다. 임의 다운로드를 root로 풀거나 실행하지 않습니다. 전체 컴파일에는 추가 의존성과 시간·공간이 필요합니다. `kernel-devel`과 전체 upstream 커널 소스는 구분하세요.

## 처음 실행할 점검

```bash
bash scripts/doctor.sh
```

이 결과는 설치 여부를 보여주는 목록입니다. MISSING이 많아도 읽기·검색은 할 수 있고, 모두 OK여도 설정·서비스까지 성공했다는 의미는 아닙니다. 개인 PC의 진단 출력에는 사용자·경로 정보가 있을 수 있으므로 자신의 기록으로 보관합니다. 자격 증명, 개인키, VM 이미지, 실제 운영 설정은 공개 저장소에 넣지 않습니다.

## 학습 기록

`templates/review.csv`를 개인 연습 폴더에 복사합니다. `question_id`는 색인의 ID, `error_reason`에는 “출발지/목적지를 반대로 읽음”, “파일 갱신 후 DB 재생성 누락”처럼 구체적인 원인을 적습니다. 자료만 읽는 회차와 자료를 닫고 재현하는 회차를 구분하세요.

# Apache HTTP Server 2.4

## 설정 위치와 핵심 지시어

Rocky 패키지 기준 `/etc/httpd/conf/httpd.conf`, `/etc/httpd/conf.d/*.conf`, `/etc/httpd/conf.modules.d/*.conf`를 확인합니다. 소스 설치는 경로가 다릅니다. `ServerRoot`는 설정·로그 등 상대경로의 기준, `DocumentRoot`는 기본 제공 콘텐츠 경로입니다.

```apache
ServerName web.example.test:80
DocumentRoot "/var/www/html"
DirectoryIndex index.html index.htm
<Directory "/var/www/html">
    Options -Indexes +FollowSymLinks
    AllowOverride None
    Require all granted
</Directory>
```

`Options Indexes`는 인덱스 파일이 없을 때 디렉터리 목록을 보여줄 수 있습니다. `FollowSymLinks`는 심볼릭 링크 처리, `AllowOverride`는 `.htaccess`에서 허용할 설정 범위를 제어합니다. `None`이면 해당 override를 허용하지 않습니다. `<Directory>`는 파일시스템 경로, `<Location>`은 URL 공간에 대한 설정이라는 차이도 읽으세요.

추가로 `Listen 8080`은 수신 포트, `ServerAdmin admin@example.test`는 관리자 연락처, `ErrorDocument 404 /errors/notfound.html`은 오류 응답 문서입니다. `Include 경로`는 다른 설정을 포함하고 `LoadModule 모듈식별자 modules/파일.so`는 모듈을 적재합니다. 예: `LoadModule userdir_module modules/mod_userdir.so`. 패키지가 이미 적재한 모듈을 중복 선언하지 않습니다.

## Basic 인증

연습용 콘텐츠 디렉터리를 만들고 비밀번호 파일을 웹 공개 경로 밖에 둡니다.

```bash
sudo mkdir -p /var/www/html/private
sudo htpasswd -c /etc/httpd/lab-users labuser
sudo chown root:apache /etc/httpd/lab-users
sudo chmod 640 /etc/httpd/lab-users
```

```apache
<Directory "/var/www/html/private">
    AuthType Basic
    AuthName "Practice area"
    AuthUserFile /etc/httpd/lab-users
    Require valid-user
</Directory>
```

`AuthName`은 인증 영역 설명, `AuthUserFile`은 해시 파일, `Require valid-user`는 등록된 사용자 허용입니다. 특정 사용자만 허용하려면 `Require user labuser`를 사용합니다. `htpasswd -c`는 새 파일 생성으로 기존 파일을 덮어쓸 수 있으므로 추가 사용자에는 `-c`를 빼세요. 실제 운영에서 Basic 인증은 HTTPS와 함께 사용합니다.

`.htaccess` 방식이라면 상위 설정에 `AllowOverride AuthConfig` 등 필요한 범위를 허용해야 합니다. 중앙 설정에 넣는 방식과 `.htaccess` 방식을 섞어 조건을 놓치지 마세요.

## UserDir

`mod_userdir`가 적재되어 있고 배포판의 `/etc/httpd/conf.d/userdir.conf`에서 해당 사용자가 허용되어야 합니다.

```apache
UserDir public_html
UserDir disabled root
<Directory "/home/*/public_html">
    AllowOverride None
    Options -Indexes
    Require all granted
</Directory>
```

배포판 기본의 `UserDir disabled`가 전체 사용자를 차단하고 있으면 설정을 조정하거나 `UserDir enabled labuser`로 조건에 맞게 허용합니다. URL은 `http://서버/~labuser/`, 실제 파일은 `/home/labuser/public_html/`입니다. 홈 상위 경로의 탐색 권한, 파일 읽기 권한, SELinux `httpd_enable_homedirs` 및 콘텐츠 라벨도 맞아야 합니다. 무조건 `chmod -R 777`로 해결하지 않습니다.

## 이름 기반 가상 호스트

```apache
<VirtualHost *:80>
    ServerName portal.example.test
    ServerAlias www.portal.example.test
    DocumentRoot /var/www/portal
    ErrorLog logs/portal_error.log
    CustomLog logs/portal_access.log combined
    <Directory "/var/www/portal">
        Require all granted
    </Directory>
</VirtualHost>
```

콘텐츠 경로를 만들고 권한을 부여한 뒤 검사합니다. Apache 2.4에서는 구형 `NameVirtualHost *:80`이 필요하지 않습니다. 2.2의 `Order`, `Allow from`, `Deny from`은 현대 `Require`와 구분해 학습합니다.

## 적용·검증·정리

```bash
sudo httpd -t
sudo httpd -S
httpd -M
sudo systemctl reload httpd
curl -I -H 'Host: portal.example.test' http://127.0.0.1/
curl -I http://127.0.0.1/private/
curl -u labuser -I http://127.0.0.1/private/
```

서비스가 꺼져 있다면 검사 후 `systemctl start httpd`가 필요합니다. `httpd -t`/`apachectl configtest`는 문법 검사, `-S`는 가상 호스트, `-M`은 모듈입니다. 인증 전 401, 올바른 인증 후 기대한 응답인지 확인합니다. 다른 VM에서는 DNS/hosts·포트·방화벽도 확인합니다. 403은 Unix 권한·Directory 인가·SELinux를 나누어 조사합니다.

소스 설치 경로에서는 `/usr/local/apache2/bin/apachectl`처럼 전체 경로가 필요할 수 있습니다. `apachectl start/stop/restart/graceful`의 차이도 확인합니다. `graceful`은 진행 중인 요청을 가능한 한 마무리하면서 설정을 다시 읽는 방식입니다. `httpd -t -D DUMP_MODULES`, `httpd -t -D DUMP_VHOSTS`도 각각 모듈·가상 호스트 확인과 연결됩니다.

실습 종료 시 추가한 conf·계정 파일·콘텐츠를 정리하고 이전 설정으로 reload하거나 스냅샷을 복원합니다. [방화벽·SELinux](firewall-ssh-selinux.md)와 함께 봅니다.

도움말: `man httpd`, `man apachectl`, `man htpasswd`, [공식 지시어 색인](https://httpd.apache.org/docs/2.4/mod/directives.html), [공식 인증 문서](https://httpd.apache.org/docs/2.4/howto/auth.html).

# 백업·복원: tar / cpio / rsync / dd / dump / xfsdump

## 어떤 단위를 다루는가

| 도구 | 주된 관점 | 선택 기준 |
|---|---|---|
| tar / cpio | 파일·디렉터리 묶음 | 필요한 파일을 아카이브로 보관 |
| rsync | 파일 트리 비교·전송 | 변경분 동기화와 원격 복사 |
| dd | 입력 바이트·블록 복사 | 장치 이미지, 정확한 블록 복제 |
| dump / restore | 지원하는 파일시스템 구조 | 주로 ext 계열의 레벨 백업·복원 |
| xfsdump / xfsrestore | XFS 파일시스템 | XFS의 전체·증분 백업 |

`/dev/sdb1`이라는 같은 경로를 받아도 읽는 방식이 다릅니다. `dd`는 파일시스템을 이해하지 않고 바이트를 복사합니다. dump는 지원하는 파일시스템의 메타데이터를 이해해서 파일을 백업합니다. 장치 경로 자체가 파일시스템의 이름은 아닙니다.

## tar: 만들기·목록·풀기

홈의 연습 파일만 사용합니다.

```bash
mkdir -p ~/backup-lab/source ~/backup-lab/restored
printf 'sample data\n' > ~/backup-lab/source/a.txt
tar -czf ~/backup-lab/data.tar.gz -C ~/backup-lab source
tar -tzf ~/backup-lab/data.tar.gz
tar -xzf ~/backup-lab/data.tar.gz -C ~/backup-lab/restored
diff -r ~/backup-lab/source ~/backup-lab/restored/source
```

`c` 생성, `t` 목록, `x` 추출, `f` 아카이브 파일 지정, `v` 상세 출력입니다. `z` gzip, `j` bzip2, `J` xz입니다. 예: `tar -xjf 파일.tar.bz2`, `tar -xJf 파일.tar.xz`. `-C`는 작업 디렉터리 변경입니다. 아카이브를 먼저 목록으로 검사하고 빈 폴더에 추출합니다. 파일 권한·ACL·SELinux·확장 속성까지 보존해야 한다면 `--acls --xattrs --selinux` 등의 지원과 권한도 검토합니다.

## cpio: 파일 목록을 입력받기

```bash
cd ~/backup-lab/source
find . -print0 | cpio --null -ov -H newc > ../data.cpio
cpio -itv < ../data.cpio
cd ~/backup-lab/restored
cpio -idmv < ../data.cpio
```

위 복원은 같은 이름의 기존 파일이 없는 새 복원 폴더를 사용합니다. `-o` copy-out(생성), `-i` copy-in(추출), `-t` 목록, `-d` 필요한 디렉터리 생성, `-m` 수정 시각 보존, `-H newc` 형식 지정입니다. `-F 파일`로 리다이렉션 대신 아카이브를 지정할 수 있습니다. `find -print0`와 `cpio --null`은 공백·줄바꿈이 있는 이름을 안전하게 전달합니다. 단순 `find . -print | cpio -ov` 형태와 옵션 의미도 연결하세요.

## rsync: 끝의 슬래시

```bash
rsync -av --dry-run ~/backup-lab/source/ ~/backup-lab/synced/
rsync -av ~/backup-lab/source/ ~/backup-lab/synced/
rsync -avz -e ssh ~/backup-lab/source/ labuser@192.0.2.30:/home/labuser/backup/
```

`source/`는 디렉터리 안의 내용, `source`는 디렉터리 자체를 복사하는 차이가 있습니다. `-a`는 재귀·다수 속성을 보존하는 archive 모드, `-v`는 상세, `-z`는 전송 압축입니다. `-a`만으로 ACL·xattr·하드 링크까지 모두 보존되지는 않습니다. `--delete`는 목적지의 파일을 삭제할 수 있으므로 조건이 요구할 때만 dry-run 후 사용합니다.

## dd: 입력과 출력 반대로 쓰지 않기

장치 백업 예시 **설명용**입니다. 대상·공간·마운트 상태를 확인한 뒤 별도로 실습합니다.

```bash
# 입력: 마운트 해제된 원본 파티션 / 출력: 다른 파일시스템의 이미지
sudo dd if=/dev/sdb1 of=/backup/lab-partition.img bs=4M status=progress conv=fsync
# 복원: 데이터를 지울 빈 대상 파티션. 원본보다 작으면 안 됩니다.
sudo dd if=/backup/lab-partition.img of=/dev/sdc1 bs=4M status=progress conv=fsync
```

`if` input, `of` output, `bs` 한 번에 읽고 쓸 단위, `count` 블록 개수입니다. 디스크 전체 `/dev/sdb`를 이미지로 만들면 파티션 테이블도 포함하지만 파티션 `/dev/sdb1` 이미지는 일반적으로 포함하지 않습니다. 사용 중인 파일시스템을 dd로 복사하면 일관성이 깨질 수 있으므로 해제하거나 적절한 스냅샷을 사용합니다. 백업 파일은 원본 파티션 안에 만들지 않습니다. 복제하면 UUID도 같아질 수 있어 동시에 연결할 때 주의합니다.

dd는 일반 파일도 입력으로 받습니다. ASCII 대소문자 변환 예:

```bash
printf 'alpha\n' > ~/backup-lab/lower.txt
dd if=~/backup-lab/lower.txt of=~/backup-lab/upper.txt conv=ucase status=none
cat ~/backup-lab/upper.txt
```

소문자 변환은 `conv=lcase`입니다. 유니코드 일반 변환기로 생각하지 마세요.

## dump / restore

먼저 `findmnt -T /mnt/labext`, `lsblk -f`로 파일시스템 종류를 확인합니다. **XFS에는 xfsdump를 사용합니다.** 다음은 ext 계열의 전용 실습 파일시스템과 외부 백업 저장소가 준비되었다는 가정입니다.

```bash
sudo dump -0u -f /backup/labext.full.dump /dev/sdb1
sudo restore -t -f /backup/labext.full.dump
mkdir -p ~/restore-ext
cd ~/restore-ext
sudo restore -r -f /backup/labext.full.dump
```

`-0`은 전체 백업 레벨, `-u`는 성공 시 dumpdates 갱신, `-f`는 출력 파일/장치입니다. 레벨 1–9는 더 낮은 레벨의 최근 백업 이후 변경분을 다룹니다. `restore -r`는 전체 파일시스템 복원용, `-x`는 선택 추출, `-i`는 대화형, `-t`는 목록입니다. 증분 복원은 전체 백업과 필요한 증분을 올바른 순서로 적용해야 합니다.

dump는 구현에 따라 파일시스템의 마운트 경로나 그 안의 파일·디렉터리를 입력받는 **부분 백업**도 지원합니다. 따라서 “파일 입력은 절대 불가능”이라고 외우지 않습니다. Rocky 8.9에서 확인한 dump 매뉴얼은 부분 백업에 **레벨0만 허용, -u 불가, 동일 파일시스템의 파일만 사용**이라는 제한을 명시합니다. tar처럼 서로 다른 파일시스템 파일들을 자유롭게 한데 묶는 도구로 이해하면 안 됩니다. 일관된 백업에는 파일시스템 정지·해제·스냅샷 정책도 필요합니다.

## xfsdump / xfsrestore

XFS가 `/mnt/labxfs`에 마운트되어 있고 `/backup`이 별도 저장소일 때:

```bash
sudo xfsdump -l 0 -L lab-full -M file -f /backup/labxfs.full.xdump /mnt/labxfs
sudo xfsdump -l 1 -L lab-inc -M file -f /backup/labxfs.inc.xdump /mnt/labxfs
mkdir -p ~/restore-xfs
sudo xfsrestore -f /backup/labxfs.full.xdump ~/restore-xfs
sudo xfsrestore -f /backup/labxfs.inc.xdump ~/restore-xfs
```

`-l`은 레벨, `-L`은 세션 라벨, `-M`은 미디어 라벨, `-f`는 백업 파일입니다. xfsrestore의 `-t`는 내용 조회, `-i`는 대화형 복원에 사용합니다. 특정 파일·하위 트리는 `xfsdump -s`의 경로 규칙과 제한을 확인합니다. 증분은 기반 전체 백업이 없으면 독립적인 완전 복원이 되지 않습니다. 열린 파일의 응용프로그램 상태까지 자동 보장하지 않으므로 DB 등은 별도 일관성 절차가 필요합니다.

## 검증과 정리

아카이브 목록 확인 → **새 경로로 복원** → `diff`, `sha256sum`, 권한·소유자 비교 순서로 확인합니다. 백업 명령의 성공 메시지만 보고 끝내지 않습니다. 홈의 `backup-lab`과 복원 폴더를 정리하고, 블록 장치 실습은 스냅샷으로 되돌립니다.

도움말: `man tar`, `man cpio`, `man rsync`, `man dd`, `man dump`, `man restore`, `man xfsdump`, `man xfsrestore`.

# BIND DNS: named.conf와 정·역방향 zone

## 조건을 네 가지로 나누기

1. 어느 영역을 관리하는가: `example.test` 또는 `2.0.192.in-addr.arpa`.
2. 어느 파일을 읽는가: named.conf의 `zone`과 `file`.
3. 어떤 정보를 답하는가: A, AAAA, NS, MX, CNAME, PTR.
4. 적용 후 무엇으로 확인하는가: named-checkconf → named-checkzone → dig.

`/etc/named.conf`는 서버 설정, `/var/named/` 아래 zone 파일은 도메인 데이터입니다. `options { directory "/var/named"; };`이면 `file "example.test.zone";`은 그 디렉터리를 기준으로 해석됩니다. chroot를 사용하는 패키지는 보이는 경로와 실제 루트가 다를 수 있습니다.

## named.conf 영역 선언

```bind
zone "example.test" IN {
    type master;
    file "example.test.zone";
    allow-update { none; };
};
zone "2.0.192.in-addr.arpa" IN {
    type master;
    file "192.0.2.rev";
    allow-update { none; };
};
```

Rocky 8 계열 BIND에서 흔한 `master` 문법을 사용합니다. 최신 문서는 `primary`라는 용어도 사용합니다. 중괄호와 문장 끝 세미콜론을 확인하세요. `allow-query`는 질의 허용, `allow-transfer`는 zone 전송 허용, `allow-update`는 동적 갱신 허용으로 역할이 다릅니다. 실습 서버를 인터넷에 무제한 재귀 DNS로 열지 않습니다.

전달·접근 관련 구문도 별도로 읽습니다.

```bind
acl labnet { 127.0.0.1; 192.0.2.0/24; };
options {
    directory "/var/named";
    listen-on port 53 { 127.0.0.1; 192.0.2.10; };
    allow-query { labnet; };
    recursion yes;
    allow-recursion { labnet; };
    forwarders { 192.0.2.53; };
    forward first;
    allow-transfer { none; };
};
```

이 options는 구조 설명용이며 실제 서버의 기존 options 블록과 합쳐야 합니다. listen-on 주소는 서버에 존재해야 하고 forwarder는 실제 동작하는 연습용 DNS여야 합니다. `forward first`는 전달 질의 실패 때 자체 재귀를 시도할 수 있고 `forward only`는 지정 전달 서버에 의존합니다. `recursion no`는 재귀 서비스를 끄며 보유한 권한 zone 질의 자체를 끈다는 뜻은 아닙니다. 전역 옵션과 zone별 옵션의 적용 범위도 구분합니다.

## 정방향 예제

실제 파일은 [examples/dns/example.test.zone](../examples/dns/example.test.zone)에 있습니다.

```dns
$TTL 1h
@ IN SOA ns1.example.test. hostmaster.example.test. (
    2026111401 ; serial
    1h         ; refresh
    15m        ; retry
    1w         ; expire
    5m )       ; negative caching TTL
  IN NS ns1.example.test.
  IN MX 10 mail.example.test.
ns1  IN A 192.0.2.10
mail IN A 192.0.2.20
web  IN A 192.0.2.30
www  IN CNAME web.example.test.
```

`@`는 현재 origin(여기서는 example.test), `$TTL`은 레코드 TTL 기본값입니다. 소유자 칸을 생략하면 앞 레코드의 소유자를 이어받으므로 NS·MX는 zone apex에 속합니다. 들여쓰기는 의미가 있습니다.

SOA의 첫 이름은 주 네임서버, 두 번째는 관리 이메일을 DNS 이름 형식으로 나타낸 값입니다. `hostmaster.example.test.`는 보통 `hostmaster@example.test`를 뜻합니다. serial은 갱신할 때 증가시키는 버전이고 날짜 모양이 필수는 아닙니다. refresh는 보조 서버의 갱신 확인 간격, retry는 실패 후 재시도, expire는 갱신하지 못한 데이터의 유효 한계입니다. SOA 마지막 필드는 현대 DNS에서 negative caching TTL 결정에 사용되며 모든 레코드의 기본 TTL과 같다고 외우지 않습니다.

**끝의 점**은 절대 이름을 뜻합니다. `web`은 `web.example.test.`로 보완되지만, 점 없는 `web.example.test`는 잘못하면 `web.example.test.example.test.`가 됩니다. MX의 숫자는 작을수록 우선입니다. MX 대상에는 일반적으로 직접 A/AAAA가 있는 호스트 이름을 쓰고 IP 주소를 바로 넣지 않습니다. CNAME 이름에는 다른 일반 데이터 레코드를 함께 두지 않습니다.

## 역방향 예제

`192.0.2.0/24`의 zone은 옥텟 순서를 뒤집은 `2.0.192.in-addr.arpa`입니다.

```dns
$TTL 1h
@ IN SOA ns1.example.test. hostmaster.example.test. (
    2026111401 1h 15m 1w 5m )
  IN NS ns1.example.test.
10 IN PTR ns1.example.test.
20 IN PTR mail.example.test.
30 IN PTR web.example.test.
```

정방향 A 레코드가 있다고 PTR이 자동 생성되지는 않습니다. `/24`가 아닌 위임은 별도 기법이 필요할 수 있으므로 무조건 마지막 옥텟 하나만 쓰는 규칙으로 일반화하지 않습니다.

## 시스템에 적용하지 않고 문법 연습

저장소 최상위에서:

```bash
named-checkzone example.test examples/dns/example.test.zone
named-checkzone 2.0.192.in-addr.arpa examples/dns/192.0.2.rev
named-checkconf examples/dns/named-check.conf
```

이것은 제공 예제의 구문 검사입니다. 실제 DNS 서버를 변경하거나 실행하지 않습니다. 의도적으로 `www` 대상의 끝 점을 지우고 검사 결과·질의 결과 차이를 비교하되, 검사기가 모든 논리 오류를 잡는다고 기대하면 안 됩니다.

## VM 서비스에 적용하는 별도 단계

`bind bind-utils`를 설치하고 기존 설정을 보관합니다. 예제 zone을 `/var/named/`에 배치하고 `root:named`, 읽기 권한과 SELinux 라벨(`restorecon`)을 확인합니다. 기존 named.conf의 options와 접근 범위를 유지하며 zone 선언만 추가합니다.

```bash
sudo named-checkconf
sudo named-checkconf -z
sudo named-checkzone example.test /var/named/example.test.zone
sudo systemctl reload named
dig @127.0.0.1 web.example.test A
dig @127.0.0.1 example.test MX
dig @127.0.0.1 -x 192.0.2.30
```

서비스가 꺼졌다면 검사 후 start합니다. `dig`에서 `status: NOERROR`, ANSWER 값, 권한 서버의 `aa` 플래그를 확인합니다. `NXDOMAIN`은 이름 부재, `NOERROR`이면서 답이 비어 있는 경우는 해당 타입 부재일 수 있습니다. 외부 VM 질의에는 listen-on·allow-query·UDP/TCP53 방화벽·네트워크가 모두 맞아야 합니다.

실습 후 추가한 zone·설정만 제거하고 reload하거나 스냅샷을 복원합니다. 이 가이드는 독자적인 예제로 개념을 설명하며 각 기출의 실제 도메인·주소·빈칸은 원문 조건에 대입해야 합니다.

도움말: `man named.conf`, `man named-checkconf`, `man named-checkzone`, `man dig`, [BIND 문서](https://bind9.readthedocs.io/en/v9.16.50/).

# 방화벽·NAT·SSH·SELinux·구형 TCP Wrapper

## 먼저 어떤 방화벽을 쓰는지 확인

```bash
systemctl is-active firewalld
sudo firewall-cmd --get-active-zones
sudo iptables -S
sudo iptables -t nat -S
ip -br address
ip route
```

Rocky 8에서는 nftables 기반 구현을 사용할 수 있습니다. firewalld와 직접 만든 iptables 규칙을 무계획하게 섞으면 상태가 어긋납니다. 기출의 명령 문법 연습과 실제 VM 방화벽 적용 방식을 구분합니다. 아래 변경 예제는 콘솔·스냅샷이 있는 별도 네트워크 실습에서만 필요한 줄을 선택해 사용합니다. SSH로 접속한 상태에서 전체 규칙을 flush하거나 기본 정책을 DROP으로 바꾸지 않습니다.

## iptables: 표와 체인

filter 표의 INPUT은 내 호스트가 받을 패킷, OUTPUT은 내 호스트가 보낼 패킷, FORWARD는 통과하는 패킷입니다. NAT의 PREROUTING은 주로 목적지 변환, POSTROUTING은 주로 출발지 변환에 사용합니다.

```bash
sudo iptables -L -n -v --line-numbers
sudo iptables -t nat -L -n -v --line-numbers
# 별도 VM에서: 특정 클라이언트의 웹 접속 허용 예
sudo iptables -A INPUT -s 192.0.2.50 -p tcp --dport 80 -j ACCEPT
```

`-A` 뒤에 추가, `-I 체인 번호` 삽입, `-D` 삭제, `-R` 교체, `-F` 비우기, `-P` 기본 정책입니다. INPUT 뒤에 기존 거부 규칙이 먼저 있으면 추가한 허용 규칙까지 도달하지 않을 수 있습니다. `--sport`는 출발지 포트, `--dport`는 목적지 포트입니다. `-i` 입력 NIC, `-o` 출력 NIC, `-s` 출발지, `-d` 목적지입니다.

`-j LOG`는 로그를 남기지만 그 자체로 최종 허용/차단 결정을 끝내지 않습니다. `--log-prefix 'LAB '` 등으로 표식을 붙인 뒤 필요한 ACCEPT/DROP 규칙을 별도로 둡니다. 규칙 번호 삭제는 현재 표의 `--line-numbers`로 번호를 확인한 뒤 `-D 체인 번호`를 쓰며 삭제할 때마다 뒤 번호가 바뀝니다.

설정 파일 저장/복원 문법:

```bash
sudo iptables-save > ~/iptables.saved
sudo sh -c 'iptables-restore < /정확한/백업경로/iptables.saved'
```

현재 메모리 규칙을 저장하는 것과 부팅 때 자동 적용하는 것은 별개입니다. iptables-services 사용 여부와 firewalld를 확인합니다.

## NAT: 주소 변환만으로 라우팅이 완성되지 않음

가정: 내부 192.0.2.0/24, 외부 NIC `enp0s3`, 외부 고정 IP 198.51.100.10, 내부 웹 서버 192.0.2.30. 실제 NIC·주소로 바꿔야 합니다.

```bash
# 외부 주소가 변하는 환경의 출발지 변환
sudo iptables -t nat -A POSTROUTING -s 192.0.2.0/24 -o enp0s3 -j MASQUERADE
# 고정 주소라면 위 규칙 대신 SNAT를 검토
sudo iptables -t nat -A POSTROUTING -s 192.0.2.0/24 -o enp0s3 -j SNAT --to-source 198.51.100.10
# 외부 8080을 내부 웹 서버 80으로 목적지 변환
sudo iptables -t nat -A PREROUTING -i enp0s3 -p tcp --dport 8080 -j DNAT --to-destination 192.0.2.30:80
```

위 MASQUERADE와 SNAT는 대안이므로 같은 조건으로 둘 다 무조건 넣지 않습니다. `net.ipv4.ip_forward=1`, FORWARD 허용, 응답 방향의 conntrack 허용, 내부 서버의 반환 경로도 필요합니다. `-m conntrack --ctstate ESTABLISHED,RELATED`는 기존 연결·관련 트래픽을 허용하는 조건입니다. 검사 호스트에서 외부 주소에 접속하고 NAT/FORWARD 규칙 카운터와 응답을 확인해야 합니다. DNAT는 로컬에서 시작한 연결과 외부에서 들어온 연결의 경로가 다를 수 있습니다.

## firewalld: runtime / permanent / zone

```bash
sudo firewall-cmd --get-default-zone
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --zone=public --list-all
sudo firewall-cmd --zone=public --add-service=http
sudo firewall-cmd --zone=public --query-service=http
sudo firewall-cmd --permanent --zone=public --add-service=http
sudo firewall-cmd --reload
sudo firewall-cmd --zone=public --list-all
```

`--permanent`만 설정하면 현재 runtime에 바로 반영되지 않습니다. reload는 permanent를 runtime에 반영하면서 기존 runtime 전용 변경을 잃을 수 있습니다. 서비스 이름 대신 포트는 `--add-port=8080/tcp`입니다. 삭제는 `--remove-service`/`--remove-port`이며 permanent도 별도로 제거해야 합니다. 실제 NIC가 다른 zone에 속하면 public에 추가해도 기대한 접속이 되지 않을 수 있습니다.

## SSH 공개키와 root 로그인 정책

```bash
ssh-keygen -t ed25519
ssh-copy-id labuser@192.0.2.10
ssh labuser@192.0.2.10
```

새 키를 생성할 때 기존 키 경로를 덮어쓰지 않습니다. `.pub`은 공개키, 확장자 없는 파일은 개인키입니다. 개인키는 서버에 배포하거나 저장소에 올리지 않습니다. 서버의 `~/.ssh/authorized_keys`, 소유자, 디렉터리700·파일600 권한, SELinux 라벨 등을 확인합니다.

```text
# /etc/ssh/sshd_config
PermitRootLogin no
```

`prohibit-password`는 root의 암호 인증을 제한하지만 공개키 인증은 허용할 수 있어 `no`와 다릅니다. 파일 수정 뒤 `sudo sshd -t`, 실제 적용 설정은 `sudo sshd -T`로 확인하고 reload합니다. Match 조건이 있으면 적용 대상에 따라 달라질 수 있습니다. 기존 세션을 유지하며 새 세션이 성공하는지 확인한 후 종료합니다.

## SELinux: 상태와 실제 차단 원인

```bash
getenforce
sestatus
ls -Zd /var/www/html
sudo ausearch -m AVC -ts recent
```

Enforcing은 정책 강제, Permissive는 거부를 기록하되 강제하지 않음, Disabled는 비활성 상태입니다. `setenforce 0/1`은 현재 실행 상태 변경이며 Disabled 상태에서 정책을 켜는 명령이 아닙니다. 영구 설정은 `/etc/selinux/config`와 부팅 절차를 확인합니다. 서비스 오류가 나면 SELinux를 끄기 전에 라벨·Boolean·AVC를 확인합니다.

`restorecon`은 기본 라벨 복원, `semanage fcontext -a -t httpd_sys_content_t '/srv/labweb(/.*)?'`는 영구 경로 라벨 정의의 예입니다. 이어서 `restorecon -Rv /srv/labweb`이 필요합니다. `semanage`는 `policycoreutils-python-utils` 패키지가 필요할 수 있습니다.

## nmap와 구형 TCP Wrapper

자신의 VM만 대상으로 `nmap -F 127.0.0.1`처럼 빠른 포트 검사를 연습합니다. 로컬 리스너는 `ss -lntup`도 함께 확인합니다. nmap의 open/closed/filtered는 서로 다르고 외부에서의 도달 가능성은 별도 검사입니다.

옛 환경의 TCP Wrapper는 `/etc/hosts.allow`를 먼저 보고, 허용되지 않으면 `/etc/hosts.deny`를 확인합니다. 예: allow의 `sshd: 192.0.2.`와 deny의 `sshd: ALL`. `daemon: client` 형식, `ALL`, `EXCEPT`가 주요 개념입니다. xinetd는 `/etc/xinetd.d/서비스`의 `disable = no`, `server`, `socket_type`, `wait` 등을 사용했습니다.

**RHEL/Rocky 8에서는 TCP Wrapper 지원이 제거된 환경이므로 hosts.allow를 만들었다고 현대 sshd 접근이 제한되는 것은 아닙니다.** 구형 기출 문법은 이론으로 분리하고 Rocky 8의 실제 제한은 firewalld·서비스 설정으로 실습합니다. `telnet`도 평문 인증이므로 실제 접속 수단으로는 SSH를 사용합니다.

정리는 추가한 규칙·서비스·SELinux 경로 정의를 정확히 제거하거나 스냅샷 복원으로 진행합니다. 도움말: `man iptables`, `man iptables-extensions`, `man firewall-cmd`, `man sshd_config`, `man ssh-keygen`, `man semanage`.

# rsyslog·로그 조회·logrotate·sysctl·IPC

## rsyslog 규칙 읽기

전통적 문법은 `facility.priority action`입니다. facility는 발생 분야, priority는 심각도, action은 저장·전송할 대상입니다. `/etc/rsyslog.conf`와 `/etc/rsyslog.d/*.conf`를 함께 확인합니다.

```text
mail.warning                     /var/log/lab-mail.log
authpriv.*                       /var/log/lab-auth.log
*.err;kern.none                   /var/log/lab-errors.log
*.emerg                          :omusrmsg:*
```

심각도는 높은 순서로 emerg(0), alert(1), crit(2), err(3), warning(4), notice(5), info(6), debug(7)입니다. `mail.warning`은 warning **이상으로 심각한** 메시지, `mail.=warning`은 warning만, `mail.!warning`은 해당 임계 범위를 제외합니다. `*`는 전체, `none`은 제외합니다. `warn`은 warning, `panic`은 emerg의 구형 별칭이며 정리에는 표준 이름을 씁니다.

| action 예 | 의미 |
|---|---|
| `/var/log/lab.log` | 파일 저장 |
| `@192.0.2.20:514` | UDP 전송 |
| `@@192.0.2.20:514` | TCP 전송 |
| `:omusrmsg:root` | 로그인한 해당 사용자 터미널에 전달 |
| `/dev/tty2` | 지정 터미널 장치 |

송신 규칙만으로 수신 서버가 생기는 것은 아닙니다. 수신 측 imudp/imtcp 모듈과 input, 방화벽도 필요합니다. 여러 규칙이 일치하면 중복 기록될 수 있습니다. `mail,cron.notice`는 두 facility에 같은 임계값을 적용하고, `mail.warning;cron.info`는 각각의 selector를 나열합니다.

VM에서 별도 설정 파일을 만든 뒤:

```bash
sudo rsyslogd -N1
sudo systemctl restart rsyslog
logger -p local0.notice 'linuxmaster lab marker'
sudo journalctl -u rsyslog --since '-5 min'
```

`local0.notice /var/log/lab-local0.log`를 설정했다면 해당 파일에서 marker를 찾아야 합니다. `-N1`은 설정 검사이며 전송·파일 기록까지 성공했다는 뜻은 아닙니다. 실습 후 추가한 설정 파일을 제거하고 다시 검사·재시작합니다.

## 로그인 기록과 시스템 로그

| 파일 / 명령 | 역할 |
|---|---|
| `/var/log/wtmp` / `last` | 로그인·로그아웃 이력 |
| `/var/log/btmp` / `lastb` | 실패한 로그인 이력 |
| `/var/log/lastlog` / `lastlog` | 사용자별 마지막 로그인 |
| `/run/utmp` / `who`, `w` | 현재 로그인 세션. 호환 경로는 환경마다 다름 |
| `/var/log/secure` | RHEL 계열 인증 관련 텍스트 로그 |
| `/var/log/messages` | 일반 시스템 텍스트 로그 |
| `dmesg` | 커널 링 버퍼 |

```bash
last -n 5
last -s -7days
sudo lastb -n 5
lastlog -u labuser
sudo tail -f /var/log/secure
sudo dmesg | tail
journalctl -b
```

`wtmp`, `btmp`, `lastlog`는 일반 텍스트가 아니므로 `cat`으로 해석하지 않습니다. 파일이 없거나 비어 있을 수 있고 로그 정책·로테이션에 따라 범위가 달라집니다. 별도 파일은 `last -f 파일`, `lastb -f 파일`로 확인합니다.

## logrotate

시스템 정책은 `/etc/logrotate.conf`, 서비스별 설정은 `/etc/logrotate.d/`를 확인합니다. 아래는 직접 만든 연습 로그용 규칙입니다.

```text
/var/log/lab-app.log {
    weekly
    rotate 4
    maxsize 20M
    missingok
    notifempty
    compress
    create 0640 root root
}
```

`weekly`는 주 단위, `rotate 4`는 보관 개수, `maxsize`는 실행 시 크기가 넘으면 시간 조건 전에도 회전할 수 있게 합니다. 매초 파일을 감시하는 설정은 아닙니다. `size`는 시간 조건과의 관계가 다르므로 `man logrotate`를 읽습니다. `create`는 새 파일의 모드·소유자·그룹입니다. btmp/wtmp의 그룹은 종종 `utmp`이므로 기존 배포판 규칙을 무조건 root:root로 바꾸지 마세요.

검사는 `sudo logrotate -d /etc/logrotate.d/lab-app`입니다. 디버그 모드는 실제 회전하지 않습니다. 강제 실행 `-f`는 **해당 연습 설정만** 대상으로 삼고 생성 파일을 확인합니다. 실제 서비스가 열린 로그 파일을 다시 여는 절차는 서비스별 `postrotate` 등도 필요합니다.

## sysctl: 실행 중인 커널 변수

```bash
sysctl net.ipv4.ip_forward
sysctl -n net.ipv4.ip_forward
cat /proc/sys/net/ipv4/ip_forward
sysctl -a 2>/dev/null | less
```

`.`으로 구분한 sysctl 키는 `/proc/sys/` 아래 경로와 대응합니다. `sysctl -w 키=값`은 현재 실행 상태 변경, `/etc/sysctl.d/90-lab.conf` 등은 영구 설정입니다. `sysctl -p 파일`은 지정 파일 적용, `sysctl --system`은 여러 설정 경로를 읽습니다. 적용 순서와 같은 키의 중복 설정도 확인해야 합니다.

```text
# 영구 설정 파일의 예. 실제 적용 전 기존 값을 기록합니다.
net.ipv4.icmp_echo_ignore_all = 1
```

위 값은 IPv4 echo 요청 응답에 영향을 주며 네트워크 전체를 끊는 방화벽 규칙과 다릅니다. 실습 후 기존 값으로 복구하고 추가 설정 파일을 제거합니다. NAT 라우팅의 IP forwarding은 방화벽 규칙과 별개입니다.

## IPC와 파일 한도

```bash
ipcs
ipcs -s
ipcs -l
ipcs -ls
cat /proc/sys/fs/file-max
cat /proc/sys/fs/file-nr
ulimit -n
```

`ipcs -s`는 System V 세마포어 목록, `-l`은 제한값, `-ls`는 세마포어 제한값입니다. 공유 메모리 `-m`, 메시지 큐 `-q`도 구분합니다. `ipcrm`은 IPC 객체를 삭제하므로 실제 사용 중인 자원을 지우지 않습니다.

`file-max`는 시스템 전체 파일 핸들 관련 한도, `file-nr`는 할당·미사용·최대값 정보입니다. 최신 커널에서 두 번째 값이 0으로 보일 수 있습니다. `ulimit -n`은 셸/프로세스의 열린 파일 디스크립터 한도라 같은 값이 아닙니다.

도움말: `man rsyslog.conf`, `man logger`, `man last`, `man lastlog`, `man logrotate`, `man sysctl`, `man ipcs`.

# Sendmail 메일 설정

## 경로부터 구분하기

Rocky의 기본 메일 전송기가 반드시 Sendmail인 것은 아닙니다. `rpm -q sendmail sendmail-cf postfix`, `systemctl status sendmail`로 확인하세요. Postfix의 설정 파일에 Sendmail 지시어를 넣는 방식으로 연습하지 않습니다.

| 경로 | 용도 | 바꾼 뒤 할 일 |
|---|---|---|
| `/etc/aliases` | 로컬 수신 이름의 별칭 | `newaliases` |
| `/etc/mail/virtusertable` | 가상 도메인별 수신 주소 매핑 | `makemap hash` |
| `/etc/mail/local-host-names` | 이 서버가 최종 수신할 도메인 목록 | Sendmail 설정 재적용 |
| `/etc/mail/access` | 접근·중계 정책 맵 | `makemap hash` 또는 패키지 Makefile |
| `/etc/mail/sendmail.mc` | 사람이 편집하는 m4 설정 소스 | sendmail.cf 재생성 |
| `/etc/mail/sendmail.cf` | Sendmail이 읽는 생성 설정 | 직접 편집과 생성 방식을 혼동하지 않기 |
| `~/.forward` | 개인 계정의 전달 설정 | 계정·권한 정책 확인 |

## aliases: 로컬 이름의 별칭

```text
# /etc/aliases에 넣을 연습용 항목
labhelp: labuser
labstaff: labuser, labadmin
labcourse: :include:/etc/mail/lab-members
```

```bash
sudo newaliases
```

콜론 왼쪽은 별칭, 오른쪽은 실제 수신 대상입니다. `newaliases`는 별칭 DB를 다시 만듭니다. 텍스트만 바꾸고 DB를 갱신하지 않으면 이전 정보가 사용될 수 있습니다. 별칭은 일반적으로 로컬 이름 기준이므로 도메인마다 같은 사용자명을 다른 사람에게 보내는 조건은 virtusertable과 연결됩니다.

`:include:`는 별도 파일에서 수신 대상 목록을 읽습니다. 예제라면 `/etc/mail/lab-members` 파일을 실제로 만들고 안전한 소유자·권한을 설정해야 합니다. `sendmail -bi`도 별칭 DB 재생성과 관련됩니다.

## virtusertable: 수신 주소 → 실제 대상

```text
# /etc/mail/virtusertable
help@alpha.example.test labuser
help@beta.example.test labadmin
@alpha.example.test labuser
```

```bash
sudo sh -c 'makemap hash /etc/mail/virtusertable < /etc/mail/virtusertable'
```

왼쪽은 가상 수신 주소, 오른쪽은 실제 계정/대상입니다. `@도메인`은 해당 도메인의 나머지 주소를 처리하는 포괄 규칙입니다. 실제 운영에서는 오타 주소를 전부 수신하게 되는 정책까지 고려합니다. `.db` 파일을 편집하는 것이 아니라 텍스트 맵을 바꾸고 DB를 생성합니다. 해당 기능을 쓰도록 sendmail.mc에 설정되어 있는지도 확인합니다.

`/etc/mail/local-host-names`에는 수신할 도메인을 한 줄씩 적습니다. 이것은 DNS MX 설정을 대신하지 않습니다. `FEATURE(virtusertable)` 등의 m4 기능, 수신 도메인, 맵 DB, 실제 Unix 계정이 서로 맞아야 합니다.

## access: 수신과 중계를 구분하기

access 맵의 `RELAY`, `REJECT`, `DISCARD`, `OK`는 역할이 다릅니다. 예를 들어 내부 특정 호스트에만 RELAY를 허용하는 설정과 이 서버가 최종 목적지인 메일을 받는 설정을 구분하세요. 모든 외부 주소에 RELAY를 허용하는 개방형 중계 설정으로 연습하지 않습니다.

```bash
sudo sh -c 'makemap hash /etc/mail/access < /etc/mail/access'
```

`From:blocked.example.test REJECT`는 발신 주소에 대한 거절 예, `Connect:192.0.2.99 DISCARD`는 접속 출처에 대한 처리 예입니다. REJECT는 오류 응답으로 거부, DISCARD는 수락한 것처럼 보이면서 폐기하는 정책이라 다릅니다. 사용할 태그·기능은 설치 버전의 access_db 문서를 확인합니다. 구형 기출의 sendmail.cf `Dj호스트명`은 이 서버의 공식 호스트명 설정과 관련되며 수신 도메인 전체 목록을 뜻하지 않습니다.

## 생성·조회·검증

배포판에 Makefile이 제공되면 내용을 확인한 뒤 `sudo make -C /etc/mail`로 생성할 수 있습니다. `sendmail-cf`가 필요할 수 있습니다. `m4 /etc/mail/sendmail.mc > ...`의 출력은 임시 파일로 만들고 성공 여부를 확인한 뒤 반영합니다. 리다이렉션 실패로 기존 설정을 빈 파일로 만드는 일을 피하세요.

```bash
sendmail -bp
sudo sendmail -bv labhelp
sudo sendmail -bt
sudo journalctl -u sendmail --since '-10 min'
sudo tail /var/log/maillog
```

`-bp`는 큐, `-bv`는 수신 주소 확인, `-bt`는 주소 규칙 시험 모드입니다. `-bv` 결과만으로 실제 외부 배송까지 성공했다고 판단하지 않습니다. 실제 연습은 격리된 VM 계정에만 보내고 수신 파일·로그를 함께 확인합니다. 서비스 재적용은 환경의 unit을 확인하고 `systemctl restart sendmail` 등으로 수행합니다.

실습 후 텍스트 설정을 복원하고 DB도 다시 생성합니다. `.mc`만 복원하고 `.cf`를 재생성하지 않으면 상태가 어긋납니다. 외부 인터넷 메일 전송에는 DNS·라우팅·중계 정책 등이 추가로 필요합니다.

도움말: `man aliases`, `man newaliases`, `man makemap`, `man sendmail`, 설치된 `sendmail-cf` 문서. [Sendmail 공식 사이트](https://www.sendmail.org/).

# DNF·RPM·gcc·커널·모듈

## DNF와 RPM의 관점

DNF는 저장소와 의존성을 고려해 패키지를 관리합니다. RPM은 설치 DB나 개별 rpm 파일을 직접 조회·조작합니다. Rocky 8의 `yum`은 DNF 기반 호환 명령이며, 문항이 특정 명령을 지정하면 그 명령의 문법으로 답합니다.

```bash
dnf search httpd
dnf info httpd
dnf list installed
dnf list available
dnf repolist --all
dnf history
dnf provides '*/named-checkzone'
sudo dnf install bind bind-utils
sudo dnf clean all
```

`info`는 설명·버전·저장소 등의 상세, `list`는 패키지 목록입니다. 설치 전 저장소 도달 여부와 패키지 이름을 확인합니다. `dnf --enablerepo=저장소ID install 패키지`는 해당 실행에서 저장소를 켜는 예입니다. 영구 활성화는 `dnf config-manager --set-enabled 저장소ID`이며 `dnf-plugins-core`가 필요할 수 있습니다. 저장소 ID는 `repolist --all`에서 확인합니다.

| 명령 | 대상과 의미 |
|---|---|
| `rpm -qa` | 설치된 패키지 전체 |
| `rpm -qi bash` | 설치 패키지 정보 |
| `rpm -ql bash` | 설치된 파일 목록 |
| `rpm -qc bash` | 설정 파일 목록 |
| `rpm -qR bash` | 필요한 의존성 |
| `rpm -qf /usr/bin/bash` | 이 파일을 제공한 설치 패키지 |
| `rpm -qip ./package.rpm` | 설치 전 rpm 파일 정보 |
| `rpm -qlp ./package.rpm` | 설치 전 rpm 파일의 파일 목록 |
| `rpm -V bash` | 설치 DB와 현재 파일 속성 비교 |

`rpm -e 패키지`는 삭제입니다. `--nodeps`는 의존성 검사를 생략하므로 학습용 옵션 식별과 실제 권장 운영 절차를 구분합니다. `dnf history undo ID`도 저장소에 필요한 구버전이 없으면 실패할 수 있습니다.

## gcc: 소스 → 오브젝트 → 실행 파일

```bash
gcc -Wall -c calc.c -o calc.o
gcc -Wall -c runner.c -o runner.o
gcc calc.o runner.o -o labcalc
./labcalc
```

`-c`는 컴파일 후 오브젝트까지 만들고 링크하지 않는 옵션, `-o`는 출력 이름입니다. `.c` 파일 여러 개를 한 명령으로 링크할 수도 있습니다. 파일 개수보다 “오브젝트만 필요한가 / 실행 파일이 필요한가”를 먼저 읽으세요. 압축 해제는 [백업 가이드](backup-restore.md)의 tar 옵션과 연결됩니다.

## make 뒤의 목표 찾기

`make`는 현재 프로젝트의 Makefile을 읽습니다. `menuconfig`, `bzImage`는 모든 프로젝트가 공통으로 제공하는 하위 명령이 아닙니다.

```bash
pwd
ls -l Makefile
make help
grep -nE '^(help|menuconfig|bzImage|modules|modules_install|clean|mrproper|distclean)[[:space:]:]' Makefile
```

위 grep은 눈에 보이는 선언을 찾는 보조 도구이며 include·패턴·변수로 생성한 모든 목표를 완전히 열거하지 못합니다. `make -n 목표`는 실행할 작업을 미리 보는 데 쓸 수 있지만 재귀 make 등이 일부 실행될 수 있어 낯선 소스를 안전하게 실행하는 장치는 아닙니다.

커널 소스가 `/usr/src/linux-4.18`에 풀려 있다는 가정:

```bash
make -C /usr/src/linux-4.18 help
uname -r
ls -ld /usr/src/* /lib/modules/"$(uname -r)"/build
```

소스 경로는 설치 상태에 따라 없을 수 있습니다. `kernel-devel`은 외부 모듈 빌드를 위한 파일을 제공하지만 일반적인 전체 커널 소스 tarball과 같지 않습니다. 배포판 실행 커널과 upstream 같은 숫자의 소스도 패치 수준이 다릅니다. 제공 경로가 있는지 직접 확인하세요.

| 커널 목표 | 의미 |
|---|---|
| `make clean` | 주로 빌드 산출물 정리, 설정은 보존 |
| `make mrproper` | 설정 `.config` 등도 정리 |
| `make distclean` | mrproper에 더해 배포 전 정리 작업 |
| `make menuconfig` | 대화형 설정. ncurses 개발 도구 등이 필요 |
| `make bzImage` | x86 커널 이미지 빌드 |
| `make modules` | 모듈 빌드 |
| `make modules_install` | 모듈 설치. 권한·대상 커널 경로 주의 |

학습 순서는 소스 확보 → 기존 설정 보관 → 필요 시 정리 → 설정 → 이미지·모듈 빌드입니다. 모든 실습에서 실제 설치·부팅 변경까지 할 필요는 없습니다. `distclean`은 저장한 설정도 지우므로 순서를 조심하세요. 커널 이미지의 `bzImage`는 bzip2 압축 파일이라는 뜻이 아닙니다.

## 모듈과 하드웨어 정보

```bash
lsmod
modinfo xfs
modprobe --showconfig | less
cat /proc/cpuinfo
cat /proc/meminfo
cat /proc/version
cat /proc/mdstat
```

`lsmod`는 적재된 모듈, `modinfo`는 모듈 정보, `insmod 파일.ko`는 파일을 직접 적재, `modprobe 모듈명`은 의존성을 고려한 적재입니다. 제거는 `rmmod 이름` 또는 `modprobe -r 이름`입니다. 여러 모듈을 적재하려면 `modprobe -a 이름1 이름2`를 사용할 수 있습니다. 스토리지·네트워크에 사용 중인 모듈을 연습 삼아 제거하지 마세요.

`depmod -a`는 `/lib/modules/커널버전/`의 의존성 DB를 갱신합니다. 관련 파일은 `modules.dep`와 `modules.dep.bin`입니다. 설정은 `/etc/modprobe.d/*.conf`이며 `alias 별칭 모듈명`, `options 모듈명 옵션=값`, `blacklist 모듈명` 등을 확인합니다. blacklist가 모든 명시적 적재까지 절대 차단하는 것은 아닙니다.

## 검증·정리

패키지는 `rpm -q 패키지`, 소유 파일은 `rpm -ql`, 소스 목표는 `make help`, 빌드 결과는 생성 파일과 반환값으로 검증합니다. 커널 설치·모듈 제거는 이 자료를 읽는 것만으로 자동 수행되지 않습니다. 설정 변경은 스냅샷으로 되돌립니다.

도움말: `man dnf`, `man rpm`, `man gcc`, `man make`, `man modprobe`, `man modinfo`. [GNU Make 매뉴얼](https://www.gnu.org/software/make/manual/make.html), [커널 빌드 문서](https://docs.kernel.org/kbuild/).

# 프로세스·우선순위·cron

## 실행 중인 프로세스 찾기와 종료

```bash
ps -eo pid,ppid,user,ni,pri,comm --sort=pid
pgrep -u labuser -a
pgrep -x sleep
```

`pgrep`는 PID 검색, `pkill`은 조건에 맞는 프로세스에 신호를 보냅니다. `pkill -u 사용자`는 해당 사용자의 여러 프로세스를 종료할 수 있습니다. 먼저 `pgrep`로 대상을 확인합니다. `kill -TERM PID`로 정상 종료를 요청하고, 응답하지 않는 경우에만 `kill -KILL PID`를 검토합니다. SIGKILL은 정리 작업을 할 기회를 주지 않습니다.

## nice / renice

NI 값은 일반적으로 -20부터 19까지이며 작을수록 CPU 스케줄링에서 유리합니다. CPU 사용량을 일정 비율로 고정하는 옵션은 아닙니다.

```bash
nice -n 7 sleep 300 &
lab_pid=$!
ps -o pid,ni,comm -p "$lab_pid"
renice -n 12 -p "$lab_pid"
ps -o pid,ni,comm -p "$lab_pid"
kill "$lab_pid"
```

`nice -n 7`은 새 프로세스의 nice 값을 부모 값에서 7만큼 조정합니다. 부모 NI=0이면 결과가 7입니다. `renice -n 12 -p PID`는 이미 실행 중인 프로세스의 목표 NI 값을 지정합니다. 일반 사용자는 자기 프로세스의 우선순위를 낮추는 변경(숫자 증가)은 할 수 있지만, 숫자를 다시 낮추는 작업은 권한 제한이 있습니다. root 권한이 필요한 예제와 구분합니다.

## cron 다섯 칸

```text
분 시 일 월 요일 실행명령
15 3 * * 1-5 /usr/bin/date >> /home/labuser/cron.log 2>&1
*/10 * * * * /usr/bin/date >> /home/labuser/cron.log 2>&1
```

첫 줄 예제는 평일 03:15, 두 번째는 매시 0·10·20·30·40·50분입니다. 분 0–59, 시 0–23, 일 1–31, 월 1–12, 요일 0–7(0과 7은 일요일)을 사용합니다. `1-5`는 범위, `1,3,5`는 목록, `*/10`은 간격입니다. 일반적인 cron에서 일과 요일을 모두 제한하면 두 조건 중 하나에 맞을 때 실행됩니다. `man 5 crontab`의 구현 설명을 확인하세요.

```bash
crontab -l
crontab -e
sudo crontab -u labuser -l
sudo crontab -u labuser -e
systemctl status crond
```

`crontab -r`는 해당 사용자 작업 전체 삭제이므로 먼저 `crontab -l > cron.saved`로 보관합니다. `/var/spool/cron/사용자명`을 직접 고치기보다 `crontab`을 사용합니다.

**개인 crontab**에는 사용자 칸이 없습니다. `/etc/crontab`과 `/etc/cron.d/*`의 **시스템 crontab**에는 다섯 시간 칸 다음에 실행 사용자 칸이 있습니다.

```text
# /etc/cron.d/lab-example
15 3 * * 1-5 labuser /usr/bin/date >> /home/labuser/cron.log 2>&1
```

cron은 로그인 셸과 환경이 다릅니다. 명령·파일은 절대경로를 사용하고 출력과 오류를 저장합니다. `%`는 특별한 의미가 있으므로 날짜 포맷 등에 쓸 때 crontab 문법에 맞게 이스케이프합니다. `cron.allow`, `cron.deny`는 crontab 사용 권한 제어 파일이며 파일 존재 조합에 따라 동작이 달라집니다.

## 검증·정리

1분 간격으로 자신의 연습 로그에 시각을 쓰는 작업 하나를 등록하고, 2회 이상 기록되는지 확인합니다. `journalctl -u crond`, `/var/log/cron`도 확인합니다. 끝나면 추가한 줄만 제거하고 저장했던 작업을 복원합니다. root나 다른 사용자의 작업을 통째로 삭제하지 마세요.

도움말: `man nice`, `man renice`, `man pgrep`, `man 1 crontab`, `man 5 crontab`.

# Samba·NFS·vsftpd

## Samba: SMB 파일 공유

서버 패키지 `samba`, 클라이언트 `samba-client`, 마운트 도구 `cifs-utils`를 구분합니다. 설정은 `/etc/samba/smb.conf`입니다.

```ini
[global]
    workgroup = LABGROUP
    server string = Practice SMB server
    security = user
    map to guest = Never

[labshare]
    path = /srv/labshare
    browseable = yes
    read only = no
    valid users = labuser
    create mask = 0660
    directory mask = 0770
```

`[global]`은 전역, `[labshare]`는 공유 이름입니다. browseable은 목록 표시, read only는 쓰기 허용 여부, valid users는 접속 허용 사용자입니다. `writable = yes`는 `read only = no`와 관련된 별칭입니다. mask는 Unix 생성 권한 제한이며 기존 파일을 모두 해당 권한으로 바꾸는 지시어가 아닙니다. `hosts allow`, `hosts deny`를 쓰는 경우 IP·네트워크 조건도 확인합니다.

`comment`는 공유 설명, `netbios name`은 서버의 NetBIOS 이름입니다. 공유를 기본 읽기 전용으로 두고 `write list = labuser`로 일부 사용자에게만 쓰기를 허용하는 구성도 가능합니다. write list는 valid users·파일시스템 권한을 대신하지 않습니다.

```bash
sudo mkdir -p /srv/labshare
sudo chown labuser:labuser /srv/labshare
sudo chmod 770 /srv/labshare
sudo smbpasswd -a labuser
testparm -s
smbclient -L //192.0.2.10 -U labuser
smbclient //192.0.2.10/labshare -U labuser
```

labuser의 기본 그룹도 labuser인 예입니다. 실제 그룹은 `id labuser`로 확인합니다. Unix 계정과 Samba 암호 DB 등록이 모두 필요합니다. `testparm` 성공은 Unix 권한·방화벽·SELinux·인증 성공까지 보장하지 않습니다. `smbclient`에서 `ls`, `put`, `get`, `quit`으로 실습합니다. 서버는 보통 `smb` unit이며 NetBIOS 기능에는 `nmb`가 추가될 수 있습니다.

SMB 마운트는 `sudo mount -t cifs //192.0.2.10/labshare /mnt/labsmb -o username=labuser`처럼 수행합니다. 마운트 경로를 먼저 만들고 암호는 프롬프트로 입력합니다. 명령행에 평문 암호를 넣지 않습니다. SELinux Enforcing에서는 공유 경로의 `samba_share_t` 라벨 등도 필요하며 `semanage fcontext`와 `restorecon`을 확인합니다.

`smb`로 시작하는 설치된 명령 검색:

```bash
compgen -c | grep '^smb' | sort -u
apropos samba
rpm -ql samba-client | grep '/bin/'
```

`compgen`은 Bash 기능입니다. 명령 후보와 매뉴얼 검색, 패키지 파일 목록은 서로 다른 검색입니다.

## NFS: exports와 exportfs

설정 `/etc/exports`:

```exports
/srv/labnfs 192.0.2.0/24(rw,sync,root_squash)
```

**클라이언트와 `(옵션)` 사이에 공백을 넣지 않습니다.** `rw/ro`는 쓰기/읽기, `sync`는 동기 응답 정책, `root_squash`는 클라이언트 root를 익명 사용자로 매핑합니다. `no_root_squash`는 그 매핑을 하지 않으므로 조건을 정확히 읽습니다. `all_squash`, `anonuid`, `anongid`도 익명 매핑과 관련됩니다. 서버·클라이언트의 UID/GID 및 실제 Unix 권한도 필요합니다.

```bash
sudo exportfs -ra
sudo exportfs -v
showmount -e 192.0.2.10
sudo mkdir -p /mnt/labnfs
sudo mount -t nfs 192.0.2.10:/srv/labnfs /mnt/labnfs
findmnt /mnt/labnfs
```

서버 공유 디렉터리 생성·권한과 `nfs-server` 시작이 선행되어야 합니다. `exportfs -r`은 다시 내보내기, `-a`는 전체, `-u`는 내보내기 해제입니다. `showmount`는 mountd 기반 조회여서 NFSv4 전용 서버에서 실패해도 모든 NFS 서비스 실패를 뜻하지 않습니다. NFSv3와 v4의 포트·경로 차이도 확인합니다.

## vsftpd: 허용 정책을 두 단계로 읽기

설정 `/etc/vsftpd/vsftpd.conf`의 대표 지시어:

```ini
anonymous_enable=NO
local_enable=YES
write_enable=YES
local_umask=027
chroot_local_user=YES
userlist_enable=YES
userlist_deny=YES
userlist_file=/etc/vsftpd/user_list
xferlog_enable=YES
```

`local_enable`은 로컬 계정 로그인, `write_enable`은 쓰기 관련 명령, `anonymous_enable`은 익명 로그인입니다. `userlist_enable=YES` 상태에서 `userlist_deny=YES`이면 목록 계정을 거부하고, NO면 목록 계정만 허용합니다. PAM의 `/etc/vsftpd/ftpusers` 거부 목록은 별도로 적용될 수 있으므로 user_list 하나만 보고 판단하지 않습니다.

`chroot_local_user=YES`는 로컬 사용자의 경로를 가둡니다. `chroot_list_enable`과 목록이 함께 쓰이면 목록의 의미가 전체 기본 정책에 따라 뒤집힐 수 있습니다. 쓰기 가능한 chroot 루트를 거부하는 버전도 있어 **루트 디렉터리는 쓰기 금지, 그 아래 업로드 디렉터리만 쓰기 허용**하는 구성을 먼저 고려합니다.

익명 업로드 조건은 `anon_upload_enable`뿐 아니라 write_enable·디렉터리 권한 등이 함께 필요합니다. `anon_mkdir_write_enable`, `anon_other_write_enable`은 각각 생성·다른 변경 동작입니다. `listen`과 `listen_ipv6`를 동시에 켜면 충돌할 수 있으므로 배포판 기본값을 확인합니다. passive FTP에는 별도 포트 범위·방화벽 설정도 필요합니다.

## 검증·정리

Samba는 testparm → 인증 접속 → 파일 쓰기/읽기, NFS는 exportfs → 클라이언트 mount → 권한별 I/O, FTP는 서비스 시작 로그 → 계정 허용/거부 → 업로드/다운로드를 확인합니다. FTP는 평문 프로토콜이므로 격리된 연습 네트워크에서 사용합니다. vsftpd에는 다른 도구의 `-t` 같은 문법 검사 옵션이 당연히 있다고 가정하지 말고 설치 버전 도움말을 확인하세요.

마운트를 먼저 해제하고 추가한 공유·계정·서비스 설정을 복원합니다. 도움말: `man smb.conf`, `man smbclient`, `man testparm`, `man exports`, `man exportfs`, `man vsftpd.conf`.

# Squid 프록시·DHCP

## 설정값을 어디서 찾는가

명령어에는 `man 명령`, 설정에는 **설정 파일 매뉴얼·패키지 문서·샘플**이 유용합니다. 설정 파일명으로 man 페이지가 반드시 제공되는 것은 아닙니다.

```bash
rpm -q squid
rpm -qc squid
rpm -qd squid
rpm -ql squid | grep -Ei 'conf|doc|example'
man -k squid
less /usr/share/doc/squid/squid.conf.documented
grep -n -A 15 '^#  TAG: http_access' /usr/share/doc/squid/squid.conf.documented
```

위 documented 경로는 Rocky 8의 Squid 패키지에서 확인한 경로이며 다른 배포판에서는 다를 수 있습니다. `man squid.conf`가 없으면 문서 파일을 찾습니다. `squid.conf.default`와 실제 사용 중인 `squid.conf`도 구분하세요. 설명이 길면 `less`에서 `/TAG: acl`처럼 찾습니다.

## Squid ACL: 이름 정의와 적용은 별개

```squid
http_port 3128
acl lab_clients src 192.0.2.0/24
acl blocked_sites dstdomain .blocked.example.test
http_access deny blocked_sites
http_access allow lab_clients
http_access deny all
```

`acl 이름 종류 값`은 조건을 정의하며, `http_access allow/deny 이름`이 접근 정책을 적용합니다. `src`는 클라이언트 IP, `dst`는 목적지 IP, `dstdomain`은 목적지 도메인, `srcdomain`은 클라이언트의 도메인 이름 판정과 관련됩니다. 출발지·목적지를 바꿔 읽지 마세요. `time`, `port`, `method` 등의 ACL도 있습니다.

접근 규칙은 위에서 아래로 검사합니다. 첫 일치 정책이 적용되므로 차단 규칙을 광범위 허용 뒤에 두면 우회될 수 있습니다. 한 `http_access` 줄의 서로 다른 ACL 이름은 대체로 AND 조건이고, 같은 ACL 목록의 여러 값은 종류에 따라 OR로 평가됩니다. 부정은 `!ACL이름`입니다.

위 짧은 예는 **ACL 개념 설명용**입니다. 실제 설치의 `Safe_ports`, `SSL_ports`, CONNECT 제한, localhost 관리자 접근 같은 기존 보호 규칙을 삭제하는 교체 파일로 사용하지 마세요. [examples/squid.conf](../examples/squid.conf)는 문법 연습용이며 마지막에 모두 거부합니다.

```bash
sudo squid -k parse
sudo squid -f "$PWD/examples/squid.conf" -k parse
```

첫 명령은 현재 기본 설정, 둘째는 지정 예제 검사입니다. `-k parse`는 설정 해석 검사이며 통신·외부 DNS·접근 정책 실제 성공 검증은 아닙니다. 서비스 적용은 기존 파일 보관 → 수정 → parse → `systemctl reload squid` 순서입니다. 테스트 주소를 실제 연습 웹 서버로 바꾼 뒤 `curl -x http://프록시IP:3128 http://연습서버/`와 `/var/log/squid/access.log`로 허용·차단을 각각 확인합니다.

그 밖에 `cache_dir`는 디스크 캐시 저장 설정, `cache_mem`은 메모리 캐시 관련 설정, `access_log`는 요청 로그, `visible_hostname`은 표시용 호스트명입니다. 모든 버전의 지시어가 같지 않으므로 `squid -v`와 버전별 문서를 함께 확인합니다.

## DHCP: 격리한 네트워크에서만 실습

다른 DHCP 서버가 있는 NAT/브리지 네트워크에 무작정 DHCP 서버를 켜면 안 됩니다. VirtualBox **내부 네트워크**에 서버·클라이언트 VM을 두고 다른 DHCP를 끈 연습 환경을 사용합니다. 서버 인터페이스에는 고정 IP가 필요합니다.

설정 `/etc/dhcp/dhcpd.conf`의 자체 예제:

```dhcpd
default-lease-time 900;
max-lease-time 7200;
option domain-name "lab.example.test";
option domain-name-servers 192.0.2.10;
subnet 192.0.2.0 netmask 255.255.255.0 {
    range 192.0.2.100 192.0.2.150;
    option routers 192.0.2.1;
    option broadcast-address 192.0.2.255;
}
host labclient {
    hardware ethernet 02:00:00:12:34:56;
    fixed-address 192.0.2.50;
}
```

lease-time은 초 단위, subnet은 네트워크 선언, range는 동적 임대 구간, routers는 기본 게이트웨이, domain-name-servers는 DNS 서버입니다. `host`는 고정 할당이고 hardware ethernet은 MAC 주소입니다. 고정 주소를 동적 풀 밖에 두어 중복을 피합니다. 서버에 직접 연결된 인터페이스와 맞는 subnet 선언이 필요합니다.

```bash
sudo dhcpd -t -cf /etc/dhcp/dhcpd.conf
sudo systemctl status dhcpd
sudo journalctl -u dhcpd --since '-10 min'
sudo less /var/lib/dhcpd/dhcpd.leases
```

문법 검사는 실제 임대 성공을 뜻하지 않습니다. 격리된 클라이언트에서 IP·게이트웨이·DNS를 임대받는지와 서버 lease를 함께 확인합니다. UDP67/68, 올바른 NIC 선택, 고정 IP를 점검합니다. 원격 접속에 쓰는 NIC를 바꾸며 연습하지 마세요.

## 정리와 도움말

Squid는 추가 ACL을 제거하고 기존 설정으로 reload합니다. DHCP 서버는 실습 종료 후 중지하고 격리 네트워크를 유지하거나 스냅샷을 복원합니다.

도움말: `man squid`, `rpm -qd squid`, `man dhcpd.conf`, `man dhcpd`. [Squid 버전별 지시어](https://www.squid-cache.org/Doc/config/), [ISC DHCP 문서](https://kb.isc.org/docs/isc-dhcp-44-manual-pages-dhcpdconf).

# 디스크·파티션·파일시스템·RAID·LVM·쿼터

## 먼저 구분하기

`/dev/sdb`는 디스크 장치, `/dev/sdb1`은 그 디스크의 파티션 장치입니다. **파티션 장치 자체가 파일시스템이라는 뜻은 아닙니다.** 파티션 안에 ext4·XFS·swap·RAID 구성원 등을 넣을 수 있습니다. 파일시스템을 디렉터리에 연결하는 작업이 mount입니다.

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT,MODEL
sudo fdisk -l
sudo blkid
findmnt /
cat /proc/partitions
```

SATA/SCSI 계열은 sda…sdz, sdaa…처럼 이름이 늘어날 수 있습니다. NVMe는 `/dev/nvme0n1`, 파티션은 `/dev/nvme0n1p1`입니다. 이름은 연결·탐색 순서에 따라 바뀔 수 있어 영구 마운트에는 UUID를 사용합니다. 하드웨어 RAID가 논리 디스크 하나를 제공하면 물리 디스크 여러 개가 리눅스에서 장치 하나로 보일 수 있습니다. NFS/SMB NAS는 보통 디렉터리 공유로 마운트하고, iSCSI는 블록 장치를 제공한다는 차이가 있습니다.

## fdisk 방식: GPT 파티션 → ext4 → mount

**아래는 `/dev/sdb`가 비어 있는 추가 연습 디스크일 때만 실행합니다.** 시스템 디스크에서는 실행하지 않습니다. 파티션 테이블 생성·포맷은 데이터를 지웁니다.

```text
$ sudo fdisk /dev/sdb
Command (m for help): p
Command (m for help): g
Command (m for help): n
Partition number: [Enter]
First sector: [Enter]
Last sector: [Enter]
Command (m for help): p
Command (m for help): w
```

`g`는 GPT 새로 만들기, `n`은 새 파티션, `p`는 확인, `w`는 쓰기입니다. 저장하기 전 취소는 `q`입니다. MBR을 요구하는 문제라면 `o`와 primary/extended 등 MBR 조건을 따릅니다. 메뉴·기본값은 버전에 따라 다르므로 `m`을 확인합니다.

```bash
sudo partprobe /dev/sdb
lsblk -f /dev/sdb
sudo mkfs.ext4 /dev/sdb1
sudo mkdir -p /mnt/labdata
sudo mount /dev/sdb1 /mnt/labdata
findmnt /mnt/labdata
df -hT /mnt/labdata
```

`partprobe` 후 커널이 사용 중이라 갱신하지 못하면 오류를 확인하고 재부팅 여부를 판단합니다. 새 장치가 보이지 않는데 포맷부터 진행하지 마세요.

## parted 방식: 같은 목표의 별도 실습

앞 실습을 한 디스크에 아래 명령을 그대로 이어서 실행하면 다시 초기화됩니다. **스냅샷을 복원하거나 다른 빈 연습 디스크를 사용합니다.**

```text
$ sudo parted /dev/sdb
(parted) print
(parted) mklabel gpt
(parted) mkpart labdata ext4 1MiB 100%
(parted) print
(parted) quit
```

```bash
sudo partprobe /dev/sdb
sudo mkfs.ext4 /dev/sdb1
sudo mkdir -p /mnt/labdata
sudo mount /dev/sdb1 /mnt/labdata
findmnt /mnt/labdata
```

`mkpart ... ext4`의 ext4는 파티션 종류를 정하는 힌트이며 ext4 파일시스템을 만들지 않습니다. 실제 생성은 `mkfs.ext4`입니다. `mkpart ... xfs`로 만들었어도 나중에 `mkfs.ext4`를 실행할 수 있습니다. 기존 내용이 있다면 포맷 과정에서 지워지며, 이름·유형 표기와 실제 파일시스템을 `blkid`로 구분해야 합니다. `parted`는 대다수 변경을 바로 적용하므로 fdisk처럼 마지막 `w`가 필요하지 않습니다. 삭제는 `rm 번호`, 끝 위치 변경은 `resizepart 번호 끝위치`이며 파일시스템 크기는 별도로 처리해야 합니다.

## 영구 마운트·점검·swap

`sudo blkid /dev/sdb1` 결과의 실제 UUID로 `/etc/fstab`에 추가합니다.

```fstab
UUID=실제-UUID /mnt/labdata ext4 defaults 0 2
```

기존 fstab을 보관하고 `sudo findmnt --verify --verbose`로 검사합니다. 연습 파티션만 `sudo umount /mnt/labdata`, `sudo mount /mnt/labdata`로 다시 마운트한 뒤 파일이 유지되는지 확인합니다. 부팅 디스크 검사·변경을 연습에 섞지 마세요.

ext 계열 오프라인 검사는 `e2fsck /dev/sdb1` 또는 `fsck -t ext4 /dev/sdb1`, XFS는 `xfs_repair /dev/sdb1`입니다. **마운트를 해제한 파일시스템**에서 수행합니다. XFS를 `fsck.xfs`로 실제 수리한다고 생각하면 안 됩니다. XFS는 `xfs_growfs 마운트경로`로 확장하며 일반적인 축소를 지원하지 않습니다. ext4 축소는 파일시스템을 먼저 축소한 뒤 파티션을 줄이는 순서를 지켜야 합니다.

swap 파일 예제(빈 공간 512MiB 이상 필요):

```bash
sudo dd if=/dev/zero of=/swap-lab bs=1M count=512 status=progress
sudo chmod 600 /swap-lab
sudo mkswap /swap-lab
sudo swapon /swap-lab
swapon --show
free -h
```

영구 설정은 `/swap-lab none swap defaults 0 0`입니다. 정리는 `sudo swapoff /swap-lab` 후 해당 fstab 줄과 파일을 지웁니다.

## mdadm: 리눅스 소프트웨어 RAID

아래는 RAID용으로 따로 준비한 **빈 `/dev/sdc1`, `/dev/sdd1`** 예제입니다. 앞의 파일시스템 실습 파티션을 재사용하지 않습니다.

```bash
sudo mdadm --create /dev/md/lab --level=1 --raid-devices=2 /dev/sdc1 /dev/sdd1
cat /proc/mdstat
sudo mdadm --detail /dev/md/lab
sudo mkfs.xfs /dev/md/lab
sudo mkdir -p /mnt/labraid
sudo mount /dev/md/lab /mnt/labraid
findmnt /mnt/labraid
```

RAID0은 스트라이핑(최소 2개, 장애 허용 없음), RAID1은 미러, RAID5는 최소 3개·1개 장애 허용, RAID6은 최소 4개·2개 장애 허용입니다. RAID는 삭제 실수·랜섬웨어까지 복원하는 백업을 대신하지 않습니다.

구성 확인 `mdadm -D 장치`, 중지 `mdadm -S 장치`, 구성원 장애 표시 `mdadm 장치 --fail 구성원`, 제거 `--remove 구성원`, 추가 `--add 새구성원`. 장애 실습 전 별도 스냅샷을 저장합니다. 자동 조립 설정은 `mdadm --detail --scan` 결과를 검토해 `/etc/mdadm.conf`에 반영하며, 부팅 관련 배열이면 initramfs도 고려합니다.

하드웨어 RAID는 제조사 관리 화면·도구에서 구성합니다. `mdadm --create`는 리눅스 소프트웨어 RAID 명령이므로 모든 RAID 컨트롤러의 물리 디스크를 관리하는 명령이 아닙니다.

## LVM: PV → VG → LV

별도의 빈 LVM용 `/dev/sdc1`, `/dev/sdd1`을 가정합니다. RAID 실습과 동시에 같은 파티션을 쓰지 않습니다.

```bash
sudo pvcreate /dev/sdc1 /dev/sdd1
sudo vgcreate labvg /dev/sdc1 /dev/sdd1
sudo lvcreate -L 1G -n lablv labvg
sudo mkfs.xfs /dev/labvg/lablv
sudo mkdir -p /mnt/lablv
sudo mount /dev/labvg/lablv /mnt/lablv
sudo pvs
sudo vgs
sudo lvs
```

`-L`은 용량, `-l`은 extent 개수/비율, `-n`은 LV 이름입니다. PV·VG·LV 상세는 `pvdisplay`, `vgdisplay`, `lvdisplay`, 탐색은 `pvscan`, `vgscan`, `lvscan`입니다. 새 PV 추가는 `vgextend labvg /dev/새파티션`, LV 확장은 예를 들어 `lvextend -L +512M /dev/labvg/lablv` 후 `xfs_growfs /mnt/lablv`입니다. VG 여유 공간과 실제 파일시스템 확장을 모두 확인합니다.

정리 순서는 마운트 해제 → `lvremove` → `vgremove` → `pvremove`입니다. 해당 장치에 필요한 데이터가 없고 다른 LV가 없는지 확인한 뒤 수행합니다. 실습 전체 초기화에는 스냅샷 복원을 권합니다.

## ext4 쿼터와 XFS 쿼터

공통: 사용자 쿼터와 그룹 쿼터, 블록 용량과 inode(파일 수), soft 한도와 hard 한도를 구분합니다. soft 한도를 넘기면 유예 기간이 적용되며 hard 한도는 즉시 제한됩니다.

ext4의 전통적 파일 기반 쿼터 예:

1. 전용 실습 파일시스템의 fstab 옵션에 `usrquota,grpquota`를 설정하고 마운트합니다.
2. 비어 있고 사용자가 작업하지 않는 실습 파일시스템에서 `sudo quotacheck -cug /mnt/labdata`로 초기화합니다. 사용 중인 파일시스템의 검사 오류를 강제 옵션으로 넘기지 않습니다.
3. `sudo quotaon -vug /mnt/labdata`, `sudo edquota -u labuser`, `sudo repquota /mnt/labdata`로 활성화·편집·확인합니다.

XFS 예: 마운트 시 `uquota` 또는 `usrquota`로 사용자 쿼터를 활성화합니다. 처음 켤 때는 해당 파일시스템을 해제하고 다시 마운트해야 할 수 있으며 루트 파일시스템은 별도 부팅 설정이 필요합니다. XFS에 ext용 quotacheck 절차를 그대로 적용하지 않습니다.

```bash
sudo xfs_quota -x -c 'state' /mnt/lablv
sudo xfs_quota -x -c 'limit -u bsoft=200m bhard=240m labuser' /mnt/lablv
sudo xfs_quota -x -c 'limit -u isoft=1000 ihard=1200 labuser' /mnt/lablv
sudo xfs_quota -x -c 'report -uh' /mnt/lablv
```

`-x`는 관리 모드, `-c`는 실행할 명령입니다. `bsoft/bhard`는 디스크 블록 사용량, `isoft/ihard`는 inode 개수입니다. root가 아닌 해당 사용자로 파일을 만들어 실제 제한까지 확인합니다.

도움말: `man fdisk`, `man parted`, `man fstab`, `man mdadm`, `man lvm`, `man xfs_quota`, `man quotacheck`. 변경 예제 전체 자동 실행은 검증하지 않았습니다. [검증 기록](../VERIFICATION.md)을 확인하세요.

# 사용자·그룹·파일 권한

## 조건을 명령으로 바꾸기

| 조건 | 확인할 개념 |
|---|---|
| 홈도 함께 생성 | `useradd -m` |
| 기본 그룹 / 보조 그룹 | `-g` / `-G` |
| 기존 보조 그룹을 유지하며 추가 | `usermod -aG` |
| 로그인 셸 변경 | `usermod -s` |
| 계정 사용 기한 / 암호 사용 기한 | `chage -E` / `chage -M` |
| 암호 잠금 | `passwd -l`, `usermod -L` |
| inode와 타임스탬프 | `stat` |
| 파일의 immutable 등 속성 | `lsattr`, `chattr` |

## 계정과 그룹 예제

별도 VM에서 관리자 권한으로 실행합니다. `labuser`, `labteam`은 연습용 이름입니다.

```bash
sudo groupadd labteam
sudo useradd -m -g labteam -s /bin/bash labuser
sudo passwd labuser
id labuser
getent passwd labuser
sudo usermod -aG wheel labuser
id labuser
sudo usermod -s /sbin/nologin labuser
getent passwd labuser
sudo usermod -s /bin/bash labuser
```

`-m`은 홈 디렉터리를 만들고 `/etc/skel`의 기본 파일을 복사합니다. `-d /home/practice`는 홈 경로를 지정합니다. 기존 계정의 홈 이동은 `usermod -d 새경로 -m 사용자`이며 사용 중인 세션·파일 권한을 확인해야 합니다. `usermod -G`만 쓰면 보조 그룹 목록이 교체됩니다. 변경한 그룹은 새 로그인에서 반영되는지 확인합니다.

```bash
sudo usermod -l labstudent labuser
sudo groupmod -n labclass labteam
sudo gpasswd -a labstudent labclass
sudo gpasswd -d labstudent labclass
sudo gpasswd -A labstudent labclass
```

`usermod -l`은 로그인 이름만 바꿉니다. 홈 경로·메일 스풀까지 자동으로 전부 바뀐다고 생각하면 안 됩니다. `gpasswd -A`는 그룹 관리자, `-a`는 구성원 추가입니다. 명령이 사용자를 요구하는지 그룹을 요구하는지 마지막 인수를 확인하세요.

## 잠금·만료

```bash
sudo passwd -S labstudent
sudo passwd -l labstudent
sudo passwd -u labstudent
sudo chage -M 60 -W 10 -I 7 labstudent
sudo chage -E 2027-12-31 labstudent
sudo chage -l labstudent
```

`-M`은 암호 최대 사용 일수, `-W`는 만료 경고 일수, `-I`는 **암호 만료 이후** 비활성화까지의 일수, `-E`는 계정 만료일입니다. `usermod -e`와 `-f`도 계정 만료일·암호 만료 후 유예를 다룹니다. 암호 잠금만으로 SSH 공개키 인증까지 모두 차단되는 것은 아닙니다. `passwd -d`는 암호를 지우는 동작으로 잠금과 다릅니다.

주요 파일:

| 경로 | 역할 |
|---|---|
| `/etc/passwd` | 사용자명, UID, 기본 GID, 홈, 셸 |
| `/etc/shadow` | 암호 해시와 만료 정보 |
| `/etc/group`, `/etc/gshadow` | 그룹 및 보호된 그룹 정보 |
| `/etc/default/useradd` | useradd 기본값. `useradd -D`로 조회 |
| `/etc/login.defs` | UID 범위·암호 기간 등 생성 기본값 |
| `/etc/skel` | 새 홈에 복사할 기본 파일 |

`useradd -D -b /home/lab -s /bin/bash`는 이후 생성할 계정의 기본값 변경입니다. 기존 계정은 따로 수정합니다. sudo 설정은 `sudo visudo`로 편집하고 `sudo visudo -c`로 검사합니다. 예: `labstudent ALL=(root) /usr/sbin/ip`는 지정한 실행 파일의 root 실행 권한입니다. 모든 명령 허용과 혼동하지 마세요.

## getent·lsattr와 로그인 정보

`getent`는 NSS 데이터베이스를 조회합니다. 로컬 파일뿐 아니라 NSS에 연결된 다른 사용자 정보 공급원을 조회할 수 있습니다.

```text
$ getent passwd labstudent
labstudent:x:1001:1001::/home/labuser:/bin/bash
$ lsattr memo.txt
----i----------------- memo.txt
```

위 출력은 설명용입니다. UID·홈·속성 열 수는 환경마다 다릅니다. `lsattr`의 `i`는 수정·삭제가 제한되는 immutable 속성입니다. 지원하는 파일시스템에서 `sudo chattr +i memo.txt`, 해제는 `sudo chattr -i memo.txt`입니다.

`who`는 로그인 세션 상세, `users`는 로그인 사용자명 목록, `whoami`는 현재 프로세스의 유효 사용자명입니다. `sudo whoami`는 보통 `root`이고 원래 로그인 계정과 다를 수 있습니다.

## 권한·링크·검색

```bash
mkdir -p ~/permission-lab/shared
chmod 700 ~/permission-lab
umask 027
touch ~/permission-lab/sample
stat ~/permission-lab/sample
ln ~/permission-lab/sample ~/permission-lab/hardlink
ln -s sample ~/permission-lab/softlink
ls -li ~/permission-lab
```

파일 생성 기본값은 보통 666, 디렉터리는 777에서 umask 비트를 제거합니다. `umask 027`이면 일반적으로 파일 640, 디렉터리 750입니다. 파일에 실행 권한을 자동으로 주지 않습니다. 하드 링크는 같은 파일시스템에서 inode를 공유하며, 심볼릭 링크는 경로를 가리킵니다.

```bash
sudo chgrp labclass /srv/labshare
sudo chmod 3770 /srv/labshare
find /usr/bin -type f -perm -4000 -print
find /usr/bin -type f -perm /6000 -print
```

`/srv/labshare`는 미리 만든 연습 디렉터리라고 가정합니다. 특수 권한 숫자는 SUID=4, SGID=2, Sticky=1입니다. 디렉터리 SGID는 새 파일의 그룹 상속, Sticky는 디렉터리 내 삭제·이름 변경 제한입니다. `-perm -6000`은 두 비트 모두, `-perm /6000`은 둘 중 하나 이상을 뜻합니다. 일반 권한도 함께 보세요. `s/S`, `t/T`의 대문자는 해당 실행 비트가 꺼진 상태입니다.

## 검증과 정리

`id`, `getent`, `chage -l`, `stat`, `ls -ld`, 실제 새 로그인으로 요구한 상태를 확인합니다. `userdel -r labstudent`는 연습 계정과 홈을 지우므로 필요한 파일을 먼저 보관하세요. 전역 기본값과 그룹 변경까지 되돌리기에는 VM 스냅샷 복원이 편합니다.

도움말: `man useradd`, `man usermod`, `man chage`, `man gpasswd`, `man chmod`, `man find`, `man getent`, `man lsattr`.

## 6. 빈 디스크 전용 실습

이 과제 전용 스냅샷을 저장합니다. 디스크마다 용도 표를 작성하고 시스템 디스크는 제외합니다.

- [ ] fdisk로 전체 크기의 GPT 파티션 하나를 만들고 ext4 → mount → 파일 작성 → unmount/remount 후 파일 유지까지 확인합니다.
- [ ] 초기 상태로 복원한 뒤 parted로 같은 목표를 달성합니다. mkpart 직후와 mkfs 직후의 `lsblk -f`를 비교합니다.
- [ ] 별도 빈 디스크들로 RAID1을 만들고 `/proc/mdstat`와 `mdadm -D`로 상태를 확인합니다.
- [ ] 다시 초기 상태에서 PV → VG → LV → XFS → mount를 만들고 LV와 파일시스템을 각각 확장해 용량을 확인합니다.
- [ ] 전용 파일시스템에서 사용자 쿼터를 활성화하고 일반 사용자로 실제 제한을 시험합니다.
- [ ] 파일시스템 종류에 맞는 백업을 만든 뒤 새 경로로 복원해 비교합니다. dd는 마운트 해제된 별도 장치만 사용합니다.

정리: 파일시스템·RAID·LVM 순서를 이해하고 스냅샷 복원. [스토리지](../topics/storage-raid-lvm-quota.md), [백업](../topics/backup-restore.md)
